# Reveal 0.67.18 修复记录（崩溃 + 有选区时缩放卡顿）

版本：versionCode 283 / versionName 0.67.18
APK：42348769 字节，com.reveal.editor
桌面只保留 `Reveal-0.67.18-debug.apk`。

## 一、崩溃：`选择并遮住` 用了已回收的位图

日志证据（`D:\qq\1\Reveal日志-1107-2239.txt`）：

```
Selection.feather(Selection.kt:575)      ← getPixels on recycled bitmap
SketchView.applySelectionEdges(SketchView.kt:9215)
SelectMaskPanel.kt:52                    ← 预览 LaunchedEffect
```

原因：`applySelectionEdges` 在参数全是 0 的时候，`m` 就是基准图 `base` 本身，于是
`selection = base` —— `selEditBase` 和 `selection` 指向同一张位图。之后任何换选区的路径
（`applySelectionSnapshot`、`quickAddAt`、`selectAll`、`clearSelection`）都会
`selection?.recycle()`，把基准图一起回收；下一次预览 `getPixels` 就崩。

改法：
- 参数全 0 时 `m = base.copy(...)`，基准图永远只归 `selEditBase` 管，绝不再和 `selection` 同一张。
- 回收前统一加 `!isRecycled` 判断（`applySelectionEdges` / `beginSelectionEdges` /
  `cancelSelectionEdges` / `revertSelectionEdges` 四处）。
- 进入 `applySelectionEdges` 时若发现 `selEditBase` 已被回收，直接置空重新取基准。

## 二、卡顿：有选区时一次捏合做了 4 次全幅分配

原来的路径：

| 时机 | 做了什么 |
|------|----------|
| ACTION_DOWN | 无条件 `packAlpha(selection)` 全幅打包（4096 就是 64MB） |
| ACTION_POINTER_DOWN | `applySelectionSnapshot` → `unpackAlpha` + `rebuildEdge()` |
| ACTION_UP | 再来一遍 `unpackAlpha` + `rebuildEdge()` |
| `rebuildEdge()` 内部 | `tracedOutline` 全图描边 + `edgeBitmap` 全幅 + `buildDimMask` 全幅 + 重启蚂蚁线 |

主线程被占用几百毫秒，表现为「手指在动但画面不动，松手后一次性跳到目标比例，然后才跟手」。

改法：
- 快照只在**真的会在按下瞬间改选区**的模式里拍：`SelectMode.QUICK`（快速选择）。
  矩形 / 椭圆 / 单行 / 单列 / 套索 / 多边形 / 魔棒拖动期间只记起点、抬手才提交，
  不需要还原，`selSnapW` 直接留 0。
- 双指落下与抬手两处的还原都以 `selSnapW > 0` 为条件 —— 其它模式下这两处**完全跳过**，
  不 unpack、不 rebuildEdge。
- 还原成功后立刻清空快照（`selSnapBefore = null` / `selSnapW = 0` / `selSnapH = 0`），
  抬手时不会再还原第二次、也不会再重建一遍派生位图。

结果：矩形/套索/魔棒/多边形 + 有选区的双指缩放 = 0 次全幅分配；快速选择模式仍是 1 次。

## 三、怎么验

1. 先做任意选区（矩形即可）→ 双指缩放/平移：应该从第一帧就跟手，不再「先卡住再跳」。
2. 套索、魔棒、多边形各来一次同样的缩放，手感应该一致。
3. 快速选择模式下再缩放一次：允许有一点点起手顿感（要还原选区），但不该卡到松手才动。
4. `选择并遮住`：把羽化/平滑/对比来回拖，然后「取消」→ 再打开面板继续拖；再走「应用」。
   不应该崩，取消后选区应该回到打开面板时的样子（不是消失）。

## 四、这次没做的

- 没有把 `rebuildEdge()` 拆成「轻量轮廓」和「完整派生位图」两档；如果以后还嫌慢，
  下一步是让缩放期间只更新轮廓、压暗图延后到手势结束再生成。
- 没有处理「选择并遮住」面板打开期间用户按撤销/重做导致基准图语义过期的情况；
  现在的表现是继续从打开时的基准算，撤销后的选区会被下一次预览覆盖。
