# 0.74.13 3D LUT 提速：色相带 / 自然饱和度 / 亮度对比度

## 一、思路（参考文献与成熟做法）
影视调色行业处理「点对点颜色映射」的标准做法是 **3D LUT**（.cube / 通用 LUT 文件）：在 RGB 立方体上采样一遍效果，运行时每像素只做 8 次查表 + 三线性插值。17³~33³ 的表就足以表达色相偏移、饱和度、自然饱和度这类映射，肉眼几乎看不出差别。
我们原来是逐像素 `Color.colorToHSV` + `Color.HSVToColor`：**每像素两次 JNI 调用**，480px 预览一次 100~200ms，拖动必然掉帧。

## 二、这次改了什么
1. 新增 `image/Lut3D.kt`：`table(n=24, f)` 采样 + `apply(src, lut)` 三线性插值（纯 Kotlin 整数/浮点运算，无 JNI）。
2. **色相带（红/黄/绿…）**：`HueSat.applyBandsLut(src, bands)`，把余弦窗 + 色相偏移采样进 24³ 表。参数变了才重建表（13824 次），拖动时每帧只查表。
3. **自然饱和度**：`Vibrance.applyLut(...)`（含肤色保护，完全沿用原公式）。
4. **亮度/对比度**：`Tone.applyLut(...)` + 把面板从「`LaunchedEffect(参数)` 主线程逐像素」改成常驻泵 + `Dispatchers.Default`。这就是「画面跟得上但参数条不跟手」的原因——主线程被占用，滑块的合成掉帧。
5. **预览底图上限** 900 → **560**：所有调色面板共用 `previewBase`，降采样换来的流畅度收益远大于清晰度损失（松手后应用的是全分辨率）。

## 三、没做
1. 黑白、色调分离虽然已经是「泵 + 后台线程」，但这次只吃到降采样的收益，没有单独做 1D LUT；如果还掉帧，下一版把它们也换成查表。
2. 渐变映射「强度」等缺失参数还没补（桌面端的渐变映射本体没有强度，强度一般在「渐变填充」图层里；我先按这个口径确认再决定加不加）。
3. 曲线吸管、液化/变形/图案图章专属参数、裁剪与画布大小、AI 仍未做。
