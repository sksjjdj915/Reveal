# 0.68.0 修复记录 · 形状工具

用户 2026-11-09 反馈两条：
1. 「形状没办法撤回，没办法调整宽高」
2. 「不管我在哪画形状，最终都会出现在画面上方」（澄清：位置跑到画布顶部，不是图层顺序）

## 一、形状改成独立图层（可撤销 / 可调宽高）

**原来**：`commitShape()` 直接用 `Canvas(activeLayer.bitmap)` 把路径画进**当前图层**——形状和人物糊在同一张位图上，所以：
- 想把形状挪一挪、改大小，只能对整层做变换，人物跟着一起变；
- 图层顺序上它就是人物层的一部分，永远压在人物上面。

**现在**（`SketchView.commitShape()`）：
- 新建一张与文档同尺寸的空位图，把路径画进去；
- 用 `insertSpotForNew()` 插到当前层上方，命名「形状 N」，并切为活动层；
- 记一步**结构步骤**：`Stroke.addedLayer / addedIndex`；
- `undo()` 里新增分支：把这一层整层摘掉；`redo()` 里插回原位（位图不 recycle，反复撤销重做都安全）；
- `strokeBytes()` 把新增层的位图计入撤销预算，连画几十个形状也不会把内存吃爆。

结果：
- 画错了按撤销 → 整个形状一层消失，一步到位；
- 想改宽高 → 选中「形状 N」层用变换工具拖角，只缩这个形状；
- 形状和人物分了层，可以单独隐藏/改不透明度/加图层样式。

## 二、落点：提交时重算坐标

**可疑点**：原来 `commitShape()` 用的是手势过程中缓存的 `shapeX0/shapeY0/shapeX1/shapeY1`（DOWN/MOVE 时算的文档坐标）。只要视图在手势期间变过一次（切换工具时参数条高度变化 → `onSizeChanged` 重算 `viewMatrix`；或缩放/平移），缓存坐标就和当前视图对不上，形状会落在别处。

**现在**：DOWN/MOVE 额外记下**屏幕坐标** `shapeViewX0/shapeViewY0/shapeViewX/shapeViewY`，提交时用 `toImage()` 按**当前**矩阵重算一次落点再画。

同时加了一条诊断日志（日志页可直接复制）：
```
[shape] p0=x,y p1=x,y view=WxH doc=WxH square=false
```
如果还偏，把这一行发我，能直接看出是换算错还是图层尺寸不一致。

## 三、顺带

- 提交后弹提示「形状已放在新图层「形状 N」，用变换可以拖角改大小」。
- 当前层没有任何像素时给中文提示，不再静默什么都不发生。

## 出厂验法

1. 在画面中间画一个矩形 → 松手后矩形**就在手指拖出来的位置**，图层列表多出「形状 1」。
2. 按撤销 → 「形状 1」整层消失；按重做 → 又回来，位置不变。
3. 选中「形状 1」→ 变换 → 拖角缩小 → 只有这个形状变小，人物不动 → 应用。
4. 连画三个形状 → 撤销三次，三层按倒序依次消失，人物层始终在。
5. 如果把某层隐藏（眼睛关掉）再画形状，形状层仍然可见（新层默认显示）。

## 没做的

- 形状仍是**像素层**，不是桌面端那种可随时改圆角/边数的矢量层（要改边数得重画）。
- 形状样式（描边/投影）走图层样式面板，形状本身不保存参数。
