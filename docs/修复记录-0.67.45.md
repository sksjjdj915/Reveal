## 已有数据

用户实测打开 `10_大图4096.psd`（4096×3072、8 位、RGB、2 个图层）：

```
解析 303995ms · 存盘 1360ms
```

## 关键反证：这份文件根本不该慢

用 psd_tools 读同一份文件（桌面 Python 环境）：

- 图层 2 个，每层 4 通道（A/R/G/B）
- 每个通道的压缩数据只有 **202KB ~ 289KB**
- 全文档压缩数据合计约 1.6MB

12,600,000 像素、1.6MB 的 RLE，纯解码在 PC 上是 **0.2 秒**级。
所以 304 秒不是「文件大」，是代码里有毛病（O(n²) 或每像素跨界调用）。

## 本版做了什么

不猜了，直接把「卡在哪一行」抓出来：

1. **分段计时**：`Psd` 里记 `lastPhase`，区分「图层 Xms / 合并图 Xms / 层数 N」，随导入完成提示一起弹出。
2. **每层计时日志**：`RevealPsd: layer i WxH ch=N Xms`。
3. **慢解析看门狗**：解析超过 12 秒时，后台线程抓一次正在解析那个线程的堆栈（取前 12 帧），
   写进 `Psd.slowStack`，同样随提示弹出：

```
解析 303995ms（图层 303900ms / 合并图 95ms / 层数 2）· 存盘 1360ms
慢在：Psd.xxx:1234 < PsdIo.yyy:567 < Psd.openFile:660
```

有这一行就能直接定位，不用再一轮轮猜。
