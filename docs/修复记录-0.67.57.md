# 修复记录 0.67.57

## 现象
4096 上画一笔：笔迹在，继续画，**前面画的那部分一点点消失**。

## 根因（0.67.56 引入）

上一版为了省时间，把笔迹预览做成「1024×1024 的窗口跟着笔尖走」：

- 笔尖在窗口内 → 只拷新的一段（很快，这是对的）；
- 笔尖走出窗口 → 把窗口挪到笔尖附近，**`crop.eraseColor(0)` 清了旧内容**再重拷。

而大图落笔期间图层根本不改（这是我们避免整张 50MB 重传纹理的手段），
所以旧内容既不在预览里、也不在图层里 —— 一挪窗口，之前画的就没了。
日志里「盖章 604ms / 预览拷贝 22ms」也说明：拷贝已经不是瓶颈了，纯粹是这个设计错了。

## 这一版的做法

**预览改成「屏幕大小的一张整笔位图」（约 4MB），不再按窗口裁。**

- 每段只把新笔迹那一小块搬到这张图上（几毫秒）；
- 整笔一直累积在这张图上，所以画多远都不会掉内容；
- 贴回屏幕时按「当前视图 × 建立时视图⁻¹」做变换，手势中途缩放/平移也不会错位；
- 上限是固定的：一张屏幕大小的图，不管画布 4096 还是 8192。

顺带修了笔头盖章的开销：尺寸和角度都没变时改走「整像素直贴」，不再缩放采样；
`Canvas` 也不再每段新建。这两处是「盖章」那 604ms 的主要来源。

## 自检（写代码时逐条对过）
1. 收笔：先把整笔缓冲合成进图层，再回收预览图 —— 顺序不能反，否则最后一帧闪一下。
2. 取消/切工具/离开页面：三条路径都回收预览图，不留悬挂位图。
3. 缩放/平移中作画：预览图按建立时的矩阵记坐标，贴回时再换算，所以不会跳到别处。
4. 选区、阿尔法锁定、画笔混合模式、带渐隐的画笔：都**不启用**这条路（照旧逐段合成），避免双重计算。

## 怎么验
1. 4096 上画一条很长的曲线，从画布一头拉到另一头 → 整条线一直在，不能越画越少。
2. 收笔的一瞬间不能闪、不能顿。
3. 画到一半双指缩一下再继续画 → 笔迹位置不能跑偏。
4. 日志里 `盖章` 应该明显小于原来（原来 604ms），`预览拷贝` 仍是几十毫秒。
