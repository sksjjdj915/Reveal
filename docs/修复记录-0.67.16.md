# Reveal 0.67.16 修复记录（按文献补算法）

版本：versionCode 281 / versionName 0.67.16
APK：42332385 字节（com.reveal.editor）
本轮把上一版自己承认「没做透」的两条按公开算法补掉。桌面测试文本 `Reveal-测试案例.txt` 未改动。

## 1. 污点修复：换成真正的插值 / 无缝克隆

原来三种模式其实是「取外圈一圈样本做加权平均再盖上去」，所以只有颜色对得上，结构和明暗都没跟上——糊、平、边界看得出。

现在三种模式分开：

| 模式 | 现在做的 | 依据 |
|---|---|---|
| 内容识别 | 把笔迹外圈当 Dirichlet 边界，在洞内解拉普拉斯方程（高斯-赛德尔迭代），颜色和明暗顺着四周走进去 | 调和插值 / harmonic inpainting（Bertalmío 等 2000 的经典框架） |
| 创建纹理 | 取外圈最近的样本加权（保留颗粒感），不迭代 | 直接纹理搬运 |
| 近似匹配 | 先在 12 个方向的外圈挑一块 3×3 纹理最像的样本整块搬进洞当初值，再解泊松方程把这块对齐到目标边界 | 无缝克隆（Pérez、Gangnet、Blake, *Poisson Image Editing*, SIGGRAPH 2003） |

关键代码：`ToolFx.spotHeal` 里的 `hole` 掩码 → 三通道浮点图 → 高斯-赛德尔迭代（泊松项 `srcAt` 提供源梯度）→ 按覆盖度软边落回 8 位；`bestRingSample` 挑样本块。

迭代次数按洞的尺寸走（`(宽高较大者 × 2).coerceIn(16, 96)`），40px 笔刷大约 3~5ms，拖动时不会卡。

## 2. 颜色替换「查找边缘」：改用 Sobel 梯度

原来只比较「右边一个像素」，噪声和纹理都会被当成边界，结果该换的地方被跳过、不该换的反而换了。
现在对亮度做 3×3 Sobel 水平/垂直梯度（`sobelX` / `sobelY`），梯度超过阈值（`容差 × 0.6 + 26`）的地方才跳过——这才是「查找边缘」该有的判据。

## 没做的（写清原因，不再含糊）

1. **完整 PatchMatch**（Barnes 等 2009）没上：它要做多轮「传播 + 随机搜索」，在手机端 40px 洞内一次也要几十毫秒，而且我们是在拖动过程中逐段实时出结果。现在的做法是「外圈候选块评分 + 泊松对齐」，接缝没了，纹理方向的匹配不如 PatchMatch 全局最优。
2. 修复画笔仍是「低频搬移 + 保留目标高频」（频率分离思路），没有做逐像素梯度域求解。理由：它现在效果已经对（不再有涂抹感），再换成完整的泊松求解会让每一下笔触都变重，收益不如风险。
3. 「所有图层取样」第一笔仍先用当前层顶（缓存后台在拍）。

## 怎么验

- 污点修复：找一张有皮肤/天空这种渐变背景的图，在渐变的中间点一下——以前会出一块平的色块，现在色块会顺着渐变走。
- 近似匹配：在被栏杆/头发切断的地方涂，边界应该看不到方形接缝。
- 颜色替换：把「限制」切到「查找边缘」，在有大片色块和细节交界的图上涂，平坦区应该被换、边缘处保持原样。
