# 修复记录 0.67.98（code 356）

日期：2026-11-09
包：`Reveal-0.67.98-debug.apk`，42480005 字节

用户报的两条：
1. 图层样式「没有文本所说的参数调整」
2. 文字用变换调整位置后撤回不了

## 一、图层样式：滑块灰着拖不动（观感上像「没有参数」）

`ui\Dialogs.kt` `LayerStylePanel` 里 12 组参数（描边 / 投影 / 外发光 / 内阴影 / 内发光 /
颜色叠加 / 渐变叠加 / 斜面和浮雕 / 光泽 / 图案叠加 / 纹理 / 等高线）的滑块都写成
`enabled = s.strokeOn` 这类条件：这一组的开关没打开时滑块是灰的、拖不动。
用户看到一排灰条，判断成「没有参数调整」。

改法：
- 全部 `enabled = s.xxxOn` → `enabled = true`，`ColorSwatchRow(s.xxxOn)` → `ColorSwatchRow(true)`
- 每个 `s = s.copy(...)` 里补 `, xxxOn = true`：拖任意滑块 / 点任意色块，自动把这一组打开
- 面板顶部加一行说明：「拖任意滑块或点色块会自动打开这一组；每行左边的小开关可以关掉」

## 二、文字变换后撤销无效（三个独立原因，都会造成「撤了没反应」）

### 1) 撤销没丢 mip 缓存

`SketchView.kt` `undo()` / `redo()` 只做了 `compositePixelStamp++` + `markDocDirty(...)`，
没走 `touchPixels()`（那里才 `dropMips()`）。而显示路径 `drawLayerRun` 在 `viewScale < 0.45`
时用的是 `mipFor()` 的 mip2/mip4 缩小副本 ⇒ 缩小状态下撤销后，屏幕还贴着「变换之后」的小图。
改：`undo()` / `redo()` 末尾补 `dropMips()`。

### 2) 描边 / 投影的叠加图缓存没失效

`styleOverlay` / `styleTop` 的缓存键是 `identityHashCode(bmp) * 31 + styleVer`。
`undo()` 里 `p.layer.styleVer++` 写在「有 16 位快照」的循环里（`val snap = p.p16Before ?: continue`），
8 位文档没有快照就永远不 ++；位图对象也没换 ⇒ 缓存命中，撤销后画面上仍盖着变换之后的
描边 / 投影。改：在像素回写的循环里直接 `p.layer.styleVer++`。

### 3) 文字面板的预览图没清掉

文字面板实时预览走 `LaunchedEffect { delay(60); renderTextSpecPreview + setPreview }`，
`EditorScreen.kt` 的 `closeAllPanels()` 只把 `showText = false`，既没 `clearPreview()` 也没清
`editTextFor` ⇒ 预览图一直挂在那一层上；之后改图层样式、做变换、撤销，屏幕画的都还是旧预览图。
改：`closeAllPanels()` 里补 `sketch?.clearPreview(); editTextFor = -1`。

### 4) 改一次文字会把整个撤销历史扔掉

`updateTextLayerSpec` / `updateTextLayer` 里原本 `undoStack.clear(); redoStack.clear()`。
改：删掉这两行，改成把这次重画当成普通一步——`replaceLayerAt(index, rendered, "编辑文字")`
（内部抓 before/incoming、`pushUndo`、`dropMips`），再 `applyTextSpec` / 字段赋值 + `styleVer++`。

## 验法

1. 加一段文字 → 图层样式 → 顶部提示可见，直接拖「大小」滑块能拖，这一组自动变蓝（开关亮起）
2. 文字层 → 变换 → 拖位置 → 应用 → 撤销：文字回到原位，投影/描边一起回去
3. 缩放画布到 40% 以下，再变换 + 撤销：画面跟着回去（不再留旧小图）
4. 打开文字面板随便改一下 → 关掉面板 → 改图层样式：立刻能看到变化（不再挂着旧预览）
5. 加文字 → 改字号 → 撤销：字号改动本身也能撤回
6. 加文字 → 变换 → 应用 → 改字号 → 撤销两次：先撤字号、再撤变换

## 这次没做的

- 图层样式（描边/投影）的改动本身不进撤销栈：改样式后按撤销撤的是上一步画笔/变换，不是样式。
  要做得加一种 `Stroke` 结构步骤，等用户点名再加。
- 没在模拟器/真机验证（用户明确说不用跑虚拟机，只检查代码）。以上结论全部来自读代码。
