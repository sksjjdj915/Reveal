## A1  图像大小 → 提示「宽高至少 16 像素」

- 现象（用户 2026-11-08 21:48 反馈）：按 A1 改图像大小时，弹窗提示「宽高至少 16 像素」。
- 相关代码：`app/src/main/java/com/reveal/editor/ui/SizeDialogs.kt:83`
  ```kotlin
  if (vw == null || vh == null || vw < 16 || vh < 16) {
      error = "宽高至少 16 像素"
  }
  ```
- 触发条件（三种都可能，待用户复述是哪一种）：
  1. 输入框被清空后直接点「确定」（`toIntOrNull()` 返回 null）；
  2. 其中一个值被改成小于 16（比如为了试单位、先打 1）；
  3. 想只改一条边，另一条框里是空的。
- 现有行为的问题：
  - 两个框互相不联动：改宽不会自动按比例算高（桌面端有「保持比例」链）；
  - 只输入一条边时不该报「至少 16」，应该按原比例算出另一条；
  - 错误只写一句，不说是哪一个框不对，也不提示「另一个框不能空」。
- 拟改法（等确认后再动）：
  1. 加「保持比例」开关（默认开）：改宽自动算高，改高自动算宽；
  2. 某一边为空时，用另一边 × 原比例补上，不报错；
  3. 错误文案改成具体：「宽度不能小于 16」「请填写高度」。

## A1/A2 后续：改完尺寸，右上角分辨率显示不刷新

- 现象（用户 2026-11-08 22:00 反馈）：做完 A1（图像大小 1080×1620）和 A2（画布大小），画面右上角的分辨率提示还是 `1024 × 1536`。
- 根因：`EditorScreen.kt:1803` 的 `docInfo = "${doc.width} × ${doc.height}"` 只在 `LaunchedEffect(pendingDoc, sketch)` 里、`attachDocument()` 时赋一次；`resizeDocument` / `resizeCanvas` 的成功回调（`EditorScreen.kt:2959-2983`）只调了 `refreshLayers()` 和 `toast(...)`，没有更新 `docInfo`。
- 所以：画布真的改了（缩放/画布大小都生效），只是顶部那行字是旧的。
- 拟改法：两个 `onApply` 里在 `refreshLayers()` 之后补 `docInfo = "$w × $h"`（画布大小、图像大小各一处）；顺带检查 `docName` 要不要跟着变（另存为时改名）。

## A4 变换：没有「应用」按钮（待确认现象后修）

- 用户反馈（2026-11-08 22:04）：点 A4「变换」后没有应用按钮，没法确认这次变换。
- 代码现状：应用/取消/自由·透视/复位这一条浮条在 `EditorScreen.kt:1909-1951`，整个 `if (transformOn)`；`transformOn` 由 `EditorScreen.kt:1736` 的 `view.onTransformChanged = { active -> transformOn = active … }` 驱动，而 `onTransformChanged(true)` 只在 `SketchView.beginTransform()`（:4003-4005）里调用；侧栏入口是 `EditorScreen.kt:3475-3478`（`onTool(TRANSFORM)` + `onTransform()` → `sketch?.beginTransform()`）。
- 因此「按钮不出现」只可能是这两种：
  1. `beginTransform()` 提前 return —— 当活动图层是**组**、或 `needBitmap(layer)` 拿不到位图时（`SketchView.kt:3985-3986`），`transformActive` 不置 true，浮条与变换框都不会出现；
  2. 变换框出来了但浮条被底部参数条挡住/挤出可视区（浮条贴在画布 Box 的 `BottomCenter`，`padding(bottom = 14.dp)`，画笔/选区参数条在同一个 Column 的下一行）。
- 拟改法（一起做）：①组/无位图层时给一句提示「这个图层没有像素，先栅格化或用文字/像素层」而不是静默；②把「应用/取消」改成常驻在变换浮条上、并且在变换激活期间把底部参数条临时替换成这条（避免遮挡）；③应用失败（返回 false）时给提示。

## A4 补充：两指时灵时不灵 + 四角含义不固定

- 用户反馈（2026-11-08 22:07）：「有时两指没反应，有时四角是缩放有时是透视，功能不明确」。
- 代码现状：变换有**两个模式**——`tfPersp=false` 是自由变换（拖角等比、拖边拉伸、双指缩放旋转），`tfPersp=true` 是透视（拖四角各自移动、双指记指位）。模式靠浮条上的「透视/自由」按钮切（`EditorScreen.kt:1929-1933`），但这条浮条现在看不见 ⇒ 用户不知道自己处在哪个模式，四角行为就「时好时坏」。
- 两指没反应的两个可能：①在透视模式下双指走 `tfPersp` 分支（`SketchView.kt:12371-12374`），只在 `pointerCount >= 2` 且四角已同步时才生效；②双指同时被画布缩放手势抢走（`zooming` 分支），两个手势在 `onTouchEvent` 里争同一个事件流。
- 拟改法：①画布左上角常驻一个小标签显示当前模式（「自由变换」/「透视变换」），并在四角画不同手柄（自由=方块、透视=圆点），一眼能分；②进入变换时**默认永远是自由变换**，透视必须显式点一次；③变换期间双指固定给图层（缩放+旋转），画布缩放改成三指，避免抢手势；④两指事件里加一条「若 200ms 内没有产生变换，落到画布手势」的兜底。

## A4 再补充：拖四角有时有反应有时没反应

- 用户反馈（2026-11-08 22:08）：「拖四角有时没反应有时有反应」。
- 根因（读码确认）：四角/四边的命中只在 **ACTION_DOWN 那一刻**判一次 —— `tfBeginDrag()`（`SketchView.kt:4207-4223`）用 `r = 34f / viewScale()` 找最近的把手，写进 `tfCorner`；一旦这次按下没落进 34 屏幕像素以内，`tfCorner = -1`，后续 `ACTION_MOVE` 就什么都不做。
  - 更常见的触发路径：先落了两根手指（或手掌碰到）→ 走双指分支，`tfCorner` 保持 -1；抬掉一根后继续拖 → 仍在 `tfCorner = -1` 状态，拖动无效；必须**抬起再重新按**才有反应。这正是「有时有、有时没有」。
  - 次要原因：把手画出来的小方块只有约 12dp，但命中半径是 34px，视觉和判定不一致；缩得越小越难按准。
- 拟改法：①`ACTION_MOVE` 里若 `tfCorner == -1` 且此时只剩一根手指，用当前点**补做一次命中判定**（懒命中）；②命中半径从 34 提到 44，并把四角手柄视觉放大到命中范围一致（画 44px 的方块/圆点，中心对准角点）；③单指落下时若在框内但离角较远，明确走「移动整层」，不要静默无响应；④双指结束后立刻按当前单指位置重做一次命中。



## A4b 图像大小「当前图层」没反应（2026-11-08 23:06，用户要求先记不改）

现象：变换 → 图像大小 → 把范围切成「当前图层（画布尺寸不变）」→ 当前层原来是 1024，改成 1080 → 确定后看着没反应。

疑似原因（未验证）：
1. 当前层模式用的是 `k = min(tw/srcW, th/srcH)`，对话框预填的是**画布** 1080×1620，
   1024×1536 按这个比例只放大 5.5%——视觉上几乎看不出来，容易被当成没反应。
2. 完成后的提示报的是**画布**尺寸（`已改为 1080 × 1620`），没有任何反馈告诉你
   「当前层现在是 1080 × 1620」或「这一层放大了 5.5%」。
3. 若这一层本来就和画布一样大，改尺寸后是「等比缩进画布再居中」，边界变化只有几像素。

下一次顺手改：
- 当前层模式改成**直接缩放到填的宽高**（不是「等比装进」），并允许超出画布；
- 完成后提示改成「当前图层已改为 W × H（放大了 x.x 倍）」；
- 图层面板那一行右侧显示层尺寸，让变化可见。
