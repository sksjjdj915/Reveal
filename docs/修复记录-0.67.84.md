# 0.67.84 修复记录（2026-11-08）

## 症状
用户：置入图片后 → 选中图层 → 变换 → 图像大小 → 改数字确定，**画面没变化**，图还是原来那么大。

## 查到的三处问题

### 1. 几何变更后没让画面缓存作废（主因）
`SketchView.afterGeometryChange()`（改尺寸/旋转都走它）只清了撤销栈、选区、预览，然后 `fitToView()` + `invalidate()`，
**没有把 `compositeDirty` 置脏、没有 `dropMips()`、没有 `compositePixelStamp++`**。

结果：合成缓存里还是旧尺寸那张图，屏幕上「看起来什么都没发生」——实际图层已经是新尺寸了。
（这也是之前「裁剪后画面像没变」的同一条根因。）

改法：
```kotlin
compositeDirty = true
compositePixelStamp++
dropMips()
```

### 2. 文档尺寸取的是「活动层」
`resizeDocument()` 用 `layers.firstOrNull()` 算源尺寸。如果第一层是调整层/组/空层（没有像素），源尺寸就会取到 0 或错的。
新增 `docPixelWidth()` / `docPixelHeight()`：取第一个**有像素**的图层；`resizeDocument` 也改成 `firstNotNullOfOrNull`。

### 3. 两个对话框的预填值不一定是文档尺寸
「图像大小 / 画布大小」原来按活动层的 bitmap 预填。改成按 `docPixelWidth/docPixelHeight` 预填。

## 顺带：结果看得见
两个操作完成后 toast 改成带真实结果：
`已改为 1080 × 1620（共 2 层）` / `画布已改为 1080 × 1620（共 2 层）`
—— 只要点了确定，就能立刻从这句话确认到底有没有生效、现在是几层。

## 怎么验
1. 新建 1080×1620 白底 → 图层面板「置入图」选一张 1024 的图。
2. 变换 → 图像大小：打开时应该显示 `1080 / 1620`（不是 1024）。
3. 改成 1620 / 2430 确定 → 画面应该整体变大，toast 显示 `已改为 1620 × 2430（共 2 层）`。
4. 再点图像大小，打开时应显示 `1620 / 2430`。

## 备注
置入的图片是按「画布 90% 内居中」画进一张**画布尺寸**的透明层的（`addImageLayer` 已如此），
所以文档缩放时它跟着一起缩放，不会单独留一个 1024 的小块。
