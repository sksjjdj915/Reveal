# 修复记录 0.67.34（code 299）

日期：2026-11-08

## 这次改了什么（3 条）

### 1. 减淡「依然不均匀」

**原因**：上一版为了让亮部不打死，给每个像素按「当前最亮通道」算了一个封顶增益 `cap = 250/maxc`。
这个封顶**依赖像素自己的亮度**——同一片颜色里稍亮的像素增益被卡死、稍暗的继续提亮，于是画出来一块亮一块不动。

**改法**：去掉按像素值的封顶，改成 **线性光下的曝光**。

- sRGB 是编码过的非线性值，直接乘等于「假曝光」：暗部提升不足、亮部先过冲。
- 曝光的物理定义就是线性光乘系数（相机传感器是线性的），所以先查表 `srgb2lin` 转线性、乘 `f`、再查表 `lin2srgbLut` 转回 8 位。
- 三通道乘同一个 `f`，色相、饱和度在数学上严格不变。
- 系数只由「这一帧新盖上去的覆盖度」决定：总曝光 = `2^(±EV × 累计覆盖度)`，逐帧指数相加正好等于总量，所以同一像素不管被几个笔头盖到、算多少帧，结果都一样 → 交叠处不再有竹节。

### 2. 加深「变成纯色、没有不透明度」

**原因**：上一版加深是「三通道减同一个量」，`sub = 亮度 × 曝光 × 覆盖度 × 2.4`。100% 覆盖度时相当于把亮度直接减到底，很快就压成纯黑块，看着就像用纯色涂了一层；边缘的软过渡也因为一下子就撞地板而看不出来。

**改法**：和减淡用同一套线性光曝光，只是系数反着来（`f = 2^(-EV)`）。乘性压暗不会把颜色减成纯黑，过渡是连续的；再给「最暗通道」设一个地板（保护色调 0.010、不保护 0.0025 线性值），整体按比例收住，色相不乱。

### 3. 两个工具的参数条「没反应」

**原因**：`dodgeStrength` / `dodgeRange` / `dodgeProtect` / `burnStrength` / `burnRange` / `burnProtect` 都是普通 `var`。
Compose 只有读到 Snapshot 状态才会重组，普通 `var` 改了界面不会更新——滑块拖了没变化、点了「保护色调」文字也不变，看起来就是完全没反应。

**改法**：六个字段全部改成 `mutableFloatStateOf` / `mutableIntStateOf` / `mutableStateOf`，外面用 get/set 暴露同名属性，其它代码一行不用改。

## 参数含义（现在的实际行为）

| 参数 | 说明 |
|---|---|
| 曝光 | 满覆盖度、100% 时最多 1.4 档。减淡提亮、加深压暗，同一个数字在两边作用相反 |
| 全部 / 阴影 / 中间调 / 高光 | 按**线性亮度**划带（阴影 <0.16、高光 >0.16 起，中间调钟形）。线性亮度才是曝光该看的量，用 sRGB 亮度会把暗部全算成阴影 |
| 保护色调 | 减淡时效果同上（曝光已经不会把色相打散）；加深时地板从 0.0025 抬到 0.010，暗部留更多细节 |

## 怎么验

1. 在一大片平涂色上竖着拖一道减淡：笔迹应该是一条**干净、均匀**的亮带，不该有斑块、也不该有横纹/竹节。
2. 同一个地方来回涂三遍：颜色应该比涂一遍更亮，但不会出现「一节一节」的台阶。
3. 换加深，在深色（接近黑）区域拖一道：应该能看出**墨色变深、颜色还在**，不是一块纯黑。
4. 加深笔迹的边缘应该是软过渡（有透明度感），不是硬边。
5. 拖动「曝光」「大小」滑块时，数字和滑块本身要跟着动；点「保护色调」文字要在开/关之间切换。
6. 减淡改完参数后切到加深：两边的曝光、范围、保护色调互不影响。

## 已知边界

- 带选区的减淡/加深仍然生效，但笔迹边缘不额外羽化（选区本身的柔边负责过渡）。
- 低 alpha（<12）的像素会被跳过：半透明像素存回位图要预乘，精度本来就差，放大后会变成彩色颗粒。
