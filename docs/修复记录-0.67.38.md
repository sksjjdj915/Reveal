# 修复记录 0.67.38（code 303）

日期：2026-11-08

## 一句话

QQ 发来的 PSD：**失败能抄下来了、日志在首页一眼就能点、收完直接进编辑器**。

## 五处改动

### 1. 首页顶栏加了常驻「日志」按钮

以前诊断日志藏在右上角「＋」菜单的第 4 项，找不到就等于没有。现在顶栏「＋」左边有个「日志」，点开就是可复制的全文，带「复制」「发送」两个键。

### 2. 所有接收失败不再用 Toast

Toast 是一闪而过的黑条，天生不能选中、不能复制——这就是你抄不到错误的原因。现在接收失败 / 导入失败一律弹同一套**可复制弹窗**（文字可长按选中，也有「复制」键）。

### 3. 接收失败现在会写日志

`Incoming.add()` 以前 6 个失败分支（读不到权限、空文件、改名失败、异常…）只给一句 Toast，**一句日志都不写**，所以你去翻日志当然是空的。现在每个分支都写一条 `RECV` 记录，内容含：

- 失败原因（人话）
- 文件名、URI、mime
- 堆上限 / 已用内存
- 异常类名 + message（如果是抛异常死的）

### 4. 接收改成「内存映射 + 1MB 缓冲 + 进度」

以前是 `openInputStream` + 8KB 缓冲纯流拷贝：几十 MB 的 PSD 很慢，而且中途没有任何反馈。现在：

- `openFileDescriptor` 拿文件描述符；
- 能拿到大小时直接 `FileChannel.map` 按 8MB 分块写（不进堆，这就是 24MB 以上解析已经在用的办法）；
- 拿不到大小（管道）退回 1MB 缓冲流拷贝；
- 进度写进 `Incoming.recvPct`，首页那张卡片会显示「正在接收… 42%」。

### 5. 落盘前验文件头 + 清单补 octet-stream

- 复制完读前 4 字节，不是 `8BPS` 就当场报「这不是 PSD 文件（文件头是 XXX）」，并删掉半成品，不再等到解析才报「导入失败」；
- `AndroidManifest.xml` 的 VIEW 清单补了 `application/octet-stream` 和 `application/x-photoshop`——QQ 给 `.psd` 常报 octet-stream，不补的话「用其他应用打开」里有时根本不出现 Reveal。

### 6. 收完直接进编辑器

以前：复制完 → 回首页 → 还弹欢迎页 → 你要自己找卡片点第二下。现在：收到就备份成工程、直接进编辑器，这一次不弹欢迎页。备份失败才回到首页并弹诊断框。

## 怎么验

1. 桌面点「日志」，应该直接出全文，能复制。
2. QQ 随手发个**不是 PSD** 的文件（比如 .txt 改名叫 .psd）→ 应该弹「这不是 PSD 文件（文件头是 …）」，点「复制」能抄走。
3. QQ 发一个正常 PSD → **直接进编辑器**，不用再点卡片，也不弹欢迎页。
4. 发一个几十 MB 的 PSD → 首页先出现「正在接收… 30%」这种带百分比的卡片。
5. 失败之后点首页「日志」→ 应该能看到 `RECV` 那几条，含 URI/mime/内存。

## 已知边界

- 内存映射要求对方给的是「有长度、可随机读」的文件描述符；QQ 从聊天里直接抛过来的通常满足，个别云盘挂载的会退回流式拷贝（也能用，只是没有进度精度）。
- 如果 QQ 那边根本没给读取权限（`openFileDescriptor` 直接返回 null），现在会明确写「对方没把读取权限给过来」，这种情况只能从 QQ 里先「保存到手机」再导入。
