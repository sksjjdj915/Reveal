# 0.74.78 范围蒙版：先对模型、再修一处

## 参考文献（结论）
影视调色软件、桌面端、局部调整工具 做的都是同一件事，只是叫法不同：
- **影视调色软件**：调色是节点式的、非破坏的；Power Window 只是挂在节点上的**蒙版**，用来把该节点的修正限制在窗口内（窗口可相加/相减/相交）。窗口不改变画面 alpha，只决定「这条修正算多少」。
- **桌面端**：调整图层 + 图层蒙版。调整先算在不透明的底图上，结果再按蒙版合成：`结果 = 底图×(1−m) + 调整后×m`，图层蒙版永远不改文档 alpha。
- **局部调整工具**：局部调整的蒙版同样是**强度的权重**，不是透明度。

统一模型（三家一致）：
```
out.rgb   = base.rgb + (corrected.rgb − base.rgb) × mask
out.alpha = base.alpha          // 永远是原图的 alpha
```
这就是「蒙版只乘到修正量上」。之前我们有两处把 alpha 也当成了可乘的量（预览合成、应用合成），所以圈外/羽化带会透出棋盘格。

## 这次改了什么
`SketchView.setPreview()` 的兜底条件从 `activeRegion >= 0` 放宽成 `activeRegion >= 0 || regionsS.isNotEmpty()`。
原因：画面上有范围、但当前没有选中项时 `activeRegion` 是 −1，兜底不生效，带蒙版的预览图就直接贴上去 → 圈外透明。这正好对上「只有圈里有颜色」的截图。
