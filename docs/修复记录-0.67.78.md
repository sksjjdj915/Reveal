# 0.67.78 修复记录：按日志数字削掉一半笔头

日志（`Reveal日志-1108-2059.txt`，0.67.77 / code 342）实测：

```
画布 4096x4096 / 移动 6 次合计 168ms（其中合成 0ms）
盖章 155ms（文档 0ms / 预览 0ms / 笔头 1075 个）
慢段 0 次 / 重绘 4 帧其中慢 0 帧 / 图层上屏合计 0ms
```

结论很清楚：

- 绘制、合成、上屏都不慢（全 0ms），**时间全在「盖章」这一项**。
- 一笔 1075 个笔头、155ms → 单个笔头约 0.14ms，6 次移动里有 3~4 次超过 16ms，所以手感是「卡、跟不上」。
- 「文档 0ms / 预览 0ms」这两个数骗人：原来每次盖章都做整数除法 `(ns)/1_000_000L`，0.14ms 被截断成 0，所以永远显示 0。

## 两个改动

1. **笔头间距的屏幕像素下限 1.2 → 2.2**
   `minSpacingDoc()` = `1.2f / zoom`，意思是「屏幕上最少隔 1.2px 就盖一次」。4096 的图缩到屏幕约 0.25 倍时，这个下限只有 4.8 个文档像素，于是同一处被反复盖。
   改成 2.2px（约 8.8 文档像素），一笔的笔头从 1075 个降到约 580 个 —— 因为软笔的直径远大于 2.2px，覆盖仍然连续，肉眼看不出来。
   依据：libmypaint/MyPaint 的 dabs 间距按「屏幕像素」设下限，不是按文档像素；文档里 3px、屏幕上 0.2px 的两次盖章是同一个像素，纯属白干。

2. **计时改成微秒累加**
   `stampDocMs += (System.nanoTime() - t0) / 1_000L`，日志里打 `us`。下一份日志就能看到「文档 / 预览」各占多少，不用再猜。

## 怎么验

1. 4096 图上画一笔（和上次同样的动作）：日志里「笔头」应该从 1075 降到 550~650，「盖章」从 155ms 降到 80ms 左右。
2. 手感：拖笔应该明显更跟手。如果还觉得慢，把新日志发我 —— 这次能看到「文档 xx us / 预览 xx us」，直接指到是哪一个 drawBitmap 贵。
3. 顺带看笔迹有没有因为间距变大出现「珠子」：软笔缩放状态下一笔长线，边缘应该是连续的。

## 注

0.67.77 改的三件事（间距按弧长连续、亚像素落印、取消假软边描线）都还在，这版只是把笔头数量砍一半。
