# 修复记录 0.67.53

## 这一版改了什么（只改一处：大图落笔跟手）

### 根因
4096×3072 图层就是一张 50MB 的位图。之前每一段笔迹都直接合成进这张图，
图层内容一变，Skia 就要把**整张 50MB 重新上传一次纹理**（改一小块也要传整张），
所以「拖着画」时每一帧都在等这个上传，表现就是笔迹一段段蹦出来、不跟手。

上一版加的计时已经把这一点证实了：
`慢段 8 次 / 合计 221ms / 最慢 31ms / 图层上屏合计 0ms` —— 慢在合成，不在重绘。

### 改法（大图专用，小图完全不变）
1. 大图（超过 1200 万像素，比如 4096×3072）落笔时**不再逐段写回图层**，
   改把这一笔的包围盒（bbox）拷进一小块临时位图 `previewCrop`；
2. 每一帧画的是「合成缓存（旧的画面，内容没变所以不用重传）+ 这一小块笔迹」，
   上传量从 50MB 降到几 MB；
3. 抬手时 `commitBrushStroke` 一次性把整笔合成进图层、记一次撤销。
   代价：落笔过程中笔迹是「浮」在画面上（不透明度/选区/蒙版的最终效果待抬笔才对），
   和 Procreate、Infinite Painter 的做法一致。

同时修了一处逻辑：`direct = canDrawDirect() || zooming || drawing`
在落笔时强制绕开合成缓存、改成每帧重画所有图层——大图上光这一步就是 100MB/帧。
现在是 `(drawing && !deferLive)`，大图落笔走缓存。

## 怎么验（就三条）
1. 打开 4096 那张图，用画笔拖一道长线：应该**跟手**，线条连续，不再一段一段蹦。
2. 抬笔后松手，笔迹应该完整保留、位置不跳；按一次撤销，整笔一起消失（不是一段段撤）。
3. 换回小图（比如 1200×900）画一笔：和以前一样，拖的时候就有笔迹。

## 已知边界
- 落笔期间笔迹按「画笔不透明度」贴预览；如果用选区/蒙版/图层透明锁定，会退回原来的逐段合成（那些情况本来就慢，但结果不会被预览骗）。
- 极长的一笔如果横跨整张画布，预览块会退化成接近全幅，效果会和以前接近（这种情况少见）。
- 如果日志里「笔迹慢」那行还出现，请把那一行发我，里面有慢段次数、最慢 ms、重绘帧数、图层上屏 ms。
