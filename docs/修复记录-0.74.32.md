# 0.74.32 重滤镜预览延迟（第一步：自适应分辨率 + 行级并行基建 + 查找边缘阈值）

## 一、为什么「参数条跟手、画面卡」
参数条是局部重组（很快）；画面是**整张预览位图重算**。之前预览固定 900px、单线程 Kotlin 逐像素，动感模糊/表面模糊/中间值/油画这类每个像素要扫邻域几十次，一帧 100~400ms，滑块的每一帧都排队算，画面就明显落后于手指。

## 二、这版做了三件事
1. **自适应预览分辨率**（渐进式降级，等价于桌面端拖动时用低分辨率代理）：`FilterDock` 记录一次实际计算耗时，超过 28ms 就把预览底图从 900 降到 640，再超过就降到 480；参数一变立刻用新底图重算，画面不再追不上。
   - 「应用」始终用全分辨率原图，成图质量不受影响。
2. **行级并行基建**：新增 `image/Parallel.kt`，`Parallel.rows(h) { y -> ... }` 走 `IntStream.range(0,h).parallel()`（JVM 公共 ForkJoinPool，Android 8+ 自带）。各线程只写自己那一行、只读源数组，无锁安全；行数 <32 时不并行（调度比计算还贵）。
   - 已经接入的：查找边缘。其余重滤镜随后逐个接（一个滤镜一个目标）。
3. **查找边缘补「阈值」**：桌面端本体确实没有参数（只有 3×3 Sobel 梯度 → 反相）。但实战里最需要的是「只留强边缘」，所以加阈值 0~100：梯度幅值低于阈值当白底、高于阈值当黑线、中间线性过渡；阈值 0 时与桌面端完全一致。

## 三、没做（下一步逐个来）
动感模糊、径向模糊、表面模糊、中间值、蒙尘与划痕、减少杂色、最小值、最大值、添加杂色、胶片颗粒、油画、水彩、球面化、镜头光晕——这些的行级并行还没接，只有自适应分辨率在兜底。0.74.x 全部只编译验证，无真机验收。
