# 0.67.60：为什么 QQ 里打不开这个 PSD（不是重试能解决的）

## 日志说了什么

```
URI：content://com.tencent.mobileqq.fileprovider/external_files/storage/emulated/999/...
异常：java.io.FileNotFoundException: No content provider: content://com.tencent.mobileqq.fileprovider/...
```

`emulated/999` 是 **QQ 分身（双开）所在的用户空间**（正常主空间是 `emulated/0`）。
Android 的多用户隔离规定：**一个用户空间里的应用，看不到另一个用户空间里的 ContentProvider**，
所以「No content provider」的意思是「这个提供方在我这里根本不存在」。

**结论：这不是「QQ 还没把文件取出来」，也不是时机问题 —— 重试 4+3 次是白等。**

## 两个能用的办法

**办法 A（最省事）：让文件离开分身的路径**

1. 在 QQ（分身里那个）打开聊天，长按 `00_主流程.psd`
2. 选「保存到手机 / 下载 / 保存到文件」
3. 回 Reveal 首页 → 点「＋」→ **从文件管理器选**刚保存的那个文件

存到「下载」目录后，它就在主空间了（`emulated/0/Download`），我们能读。

**办法 B：用主空间的聊天工具发**

微信文件传输助手 / 主空间 QQ 发给自己 → 在 Reveal 首页的「QQ/微信发来的」卡片里点一下，
或者直接在那边点「用其他应用打开」选 Reveal。主空间的文件系统我们完全有权读。

## 这一版软件改了什么

以前这句报错会误导你去「等一秒再点一次」。现在：

- 认出 URI 里是别的用户空间（或异常是 `No content provider`）时，直接说清楚是**分身隔离**；
- 提示里给出上面的办法（长按文件 → 保存到手机 → 用「＋」导入）；
- 不再做那 4+3 次无意义的重试，省你七八秒。

## 顺带一句
如果你平时就是靠分身收文件，建议固定用办法 A：QQ 里长按 → 保存到手机，
之后从「＋」导入。主空间与分身的文件，系统层面就是两个世界，软件绕不过去。
