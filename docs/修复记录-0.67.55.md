# 修复记录 0.67.55

## 0.67.54 日志读出的新数字

```
移动 2 次合计 1328ms / 盖章 145ms / 预览拷贝 1103ms
```

两件事被量化了：
- **预览拷贝 1103ms / 2 次移动 ≈ 550ms 一次** —— 比原来更糟，因为它跟「这一笔拖了多大范围」成正比；
- **盖章 145ms / 2 次 ≈ 72ms 一次** —— 大笔刷一段要盖十几下，每下都往 50MB 缓冲写一趟。

## 为什么拷贝会到 550ms

预览块的大小 = **整笔的包围盒**。你一笔拖遍画布，它就从 200×200 长到 4096×3072：
- 长到 4096×3072 那一步要新建一张 **50MB 位图**，还要把旧内容搬进去，再拷这一段；
- 之后每段都在这么一大张图上做 `drawBitmap`，还要叠加 GC 压力。

这跟 MyPaint 的瓦片思路正好相反：**只处理「看得见的那几块」**，屏幕外的东西不该参与预览。

## 这一版改了两处

1. **预览块只保留屏幕范围内那部分**（`visibleDoc` ∩ 笔迹包围盒）。
   屏幕外的笔迹本来也看不见；这样预览块永远≈屏幕大小，不再随笔画变长而膨胀。
2. **大图上笔头间距抬到笔刷的 9%**（原来按默认 spacing，225 号笔刷一段要盖十几下）。
   盖的次数量级从「十几」降到「两三下」。软边笔头之间本来就重叠，视感上仍是一条连续笔迹。

## 怎么验
1. 4096 上**一笔拖遍整张画布**（这是最狠的情况）：应该跟手，不该越拖越顿。
2. 用**大笔刷**（200 以上）画：线条应该还是连续的，不能看出一个个圆点。
3. 再看日志「笔迹慢」那行：`盖章` 和 `预览拷贝` 两个数应该都掉到几十毫秒以内（原来是 72 / 550）。
