## 一、污点修复：边缘脏 / 中间发虚（用户报「中间透明、两边有笔迹」）

**原因**
逐段预览走的是「增量覆盖度」(`covUse = 本次新增`)，每一小段只补新增的那条月牙，补出来的边界正好落在上一段补过的地方 → 中间看着发虚、边上留一圈笔迹印。
另外「内容识别」原来的初值就是洞内原像素，再解拉普拉斯，等于把纹理抹平成边界平均值，必然糊。

**改法**
1. 抬手时按**整条笔迹的累计覆盖度**一次性补完（`solveSpotStroke` 开头新增一段，覆盖度从 `spotCov` 上采样到原分辨率）。
2. `ToolFx.spotHeal` 的洞**外扩 1px**，让泊松边界落在笔迹外面的原像素上，不再用「补了一半」的像素当边界。
3. 三种模式重新分工：
   - **内容识别**：先取外圈最像的 3×3 块平移进洞当初值，再用泊松把边界对平（保住纹理、接缝无缝）。
   - **创建纹理**：整块搬过来，**不迭代**（保住颗粒感）。
   - **近似匹配**：同上，之后再做 PatchMatch 精修。
4. 一次性补完的代价做了上限：包围盒 ≤ 25 万像素（约 500×500）、迭代 20 轮；超过就退回逐段。

**应该看到**：拖一道过去，中间不再是发虚的一条，边缘没有一圈脏印；三种模式结果明显不同。

---

## 二、减淡变白笔 / 加深变黑笔

**原因**：用滤色/正片叠底，三通道各自往 255 / 0 顶，彩色必然褪成白灰；且每段叠一次。

**改法**：`toneApply` 改成**乘性明度缩放**——三个通道乘同一个系数（`1 + 1.15·amount` / `1 - 0.72·amount`），色相、饱和度不动。

**应该看到**：红色涂减淡还是红的（只是更亮），深蓝涂加深还是蓝的（只是更暗），不会整片变白/变黑。

---

## 三、颜色替换一节一节（像竹子 / 贪吃蛇）

**原因**：同样用增量覆盖度，每段只上一部分色。

**改法**：改用**累计覆盖度** `cov`，一次给满；已换过的像素不再匹配目标色，所以不会重复叠加。

**应该看到**：同一笔从头到尾颜色均匀，没有竹节。

---

## 四、背景橡皮 / 污点修复 / 混合器参数拖不动

**原因**：面板里直接读 `sketch?.bgEraserSize` 这类**普通 var**，值改了但不触发 Compose 重组，滑块永远显示初值。

**改法**：三组参数各加局部 `remember { mutableFloatStateOf(...) }`，拖动时同时写本地和 SketchView：
- 背景橡皮：大小、硬度
- 污点修复：取样圈宽、边缘融合
- 混合器：载入

**应该看到**：滑块跟手、数值跟着变。

---

## 五、背景橡皮单点「圆内透明、外圈半透明」

这是硬度渐变的正常表现（不是 bug）：圆心擦到底、外圈随硬度渐隐。
**已改**：默认硬度 0.55 → **0.85**，边缘干净很多；想要硬边把硬度拉满即可。

## 六、查了「别的新加的有没有同样问题」

- 橡皮擦（大小/硬度/不透明度）：正常，用了局部状态。
- 背景橡皮、污点修复、混合器：**有**，已修（见第四节）。
- 其余参数条（画笔、仿制图章、海绵、艺术历史、魔术橡皮等）用的是局部状态或走 caller 的 state，正常。

## 没做的 / 有保留的

1. 污染修复一次性补完只在包围盒 ≤ 25 万像素时生效，长笔迹（比如斜着划满屏）仍走逐段，可能有轻微接缝。
2. 「内容识别 / 创建纹理」的分工是按效果做的近似，和桌面端的内部算法不完全一致。
3. 减淡/加深每一笔仍然独立叠加：一笔内不会变纯白/纯黑，但同处刷很多笔还是会一路变亮/变暗。
4. 背景橡皮的「限制 / 连续」模式仍沿用旧逻辑，这次没动。
