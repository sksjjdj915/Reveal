# 0.67.95（versionCode 353）修复记录

出包时间：2026-11-09　APK：42,480,001 字节　桌面文件：Reveal-0.67.95-debug.apk

本版按用户确认的 12 项清单逐项修完，全部有代码改动 + 编译通过 + 模拟器抽验。

## 1. 删层不可撤销（T4）

- 位置：`app/src/main/java/com/reveal/editor/ui/SketchView.kt`
- 现象：删掉一个图层后按撤销没反应（`deleteActiveLayer()` 里直接 `undoStack.clear()/redoStack.clear()`，把历史全丢了）。
- 改法：`Stroke` 增加 `removedLayer: Layer?` / `removedIndex: Int` / `isStruct()`；删除时不再清栈，改为 `pushUndo(Stroke().also { it.label = "删除图层"; it.removedLayer = gone; it.removedIndex = at })`；`undo()` 把图层插回原位置并更新 activeIndex、刷快照，`redo()` 再移除；`strokeBytes()` 把 `removedLayer.bitmap` 的字节计入，防止撤销栈撑爆内存。
- 验法：删一个图层 → 点 ↶ 撤销 → 图层回来；点 ↷ 重做 → 又消失。

## 2. 快速选择会消失（T1）

- 位置：`SketchView.kt` `commitShape()`
- 现象：活动层是调整层 / 组 / 空层（没有 bitmap）时，`val bmp = activeLayer?.bitmap` 为空直接 `return`，一点选区都不出来。
- 改法：`activeLayer?.bitmap ?: layers.firstNotNullOfOrNull { it.bitmap }`，都没有才提示「这一层没有像素，先选一个画过东西的图层」。

## 3. 减选后残留很细的蚂蚁线（T2）

- 位置：`SketchView.kt` `commitShape()` 里的 `selOutline = when { … }`
- 原因：矢量路径相减时，原边界会留下极细缝隙（paper.js 同类 bug 叫 boolean shared cuts），描边后就成了一条多余的线。
- 改法：`effOp == SelectOp.SUB` 时不再用相减路径，直接用合并后的遮罩重新描（`-> traced`）。

## 4. 图像大小选「当前图层」看不出变化（T6）

- 位置：`SketchView.kt:11603` `resizeDocument()` 的 `resizeOnlyActive` 分支
- 原因：原来 `k = min(tw/src.width, th/src.height)` 只等比装进目标框，1024×1536 → 1080×1620 只放大 5.5%，肉眼看不出。
- 改法：直接 `Bitmap.createScaledBitmap(src, tw, th, true)`，再居中贴回 `docW × docH` 画布（画布尺寸不变，超出部分裁掉）；toast 说明「已把当前图层缩放为 W × H（画布仍是 …）」。

## 5. 调整图层通用容器（T10）

- 位置：`image/AdjustOp.kt`、`ui/SketchView.kt`、`ui/EditorScreen.kt`
- 内容：新增 `KIND_CONTAINER = 4` 与 `children: List<AdjustOp>`；`flatten()`、`isNeutral()`、`title()/summary()`、`withChild()`、`withoutChild()`。渲染走 `applyContainerToTarget()` → `applyOpChainToBitmap()`（分 128 行带处理，色阶编译成 768 长表、渐变映射编译成 256 长表，避免逐像素分支）。
- 入口：「新建调整层 → 空调整组（可叠加多个）」；面板标题行的「＋叠加」可加 亮度/对比度、色相/饱和度、色阶、渐变映射。
- 性质：一个调整层里挂多个效果，等效桌面端里一堆调整层叠一起（用户原话：不想建一堆层）。

## 6. 弹窗高度按条目自适应（T7）

- 位置：`ui/EditorScreen.kt:3422`
- 原来固定 `popH = 215`（3 行），调色 29 项、滤镜 40+ 项被挡住，用户以为功能不存在。
- 改法：按条目算行数 `rows = 分组标题数 + Σceil(条目数/4)`，`popH = (rows*54+24).coerceIn(120, 430)`。

## 7. 滤镜日志补「完成 + 耗时」（T8）

- 位置：`SketchView.kt` `applyFilterToActive()` 的 `post{}` 内
- 新增 `Diag.append(context, "filter 完成", "name=… 耗时=…ms size=… 选区内 堆 …")`，和原来的 filter 开始行配对，日志里能看出每个滤镜跑了多久。

## 8. 撤销跳过空步骤（T5）

- 位置：`SketchView.kt` `undo()` / `redo()`
- 原来栈顶若是「只改选区 / 只改结构以外什么都没改」的空步骤，按撤销画面不变。改成循环丢弃 `patches.isEmpty() && selW <= 0 && !isStruct()` 的步骤。

## 9. 新建画布记住上次尺寸（T9）

- 位置：`ui/Dialogs.kt` `NewDocumentDialog`、`ui/HomeScreen.kt`
- 尺寸存 `SharedPreferences("reveal_settings")` 的 `new_doc_w` / `new_doc_h`，对话框接受 `initialW/initialH` 预填。

## 10. 渐变映射多色标（T11）

- 位置：`image/AdjustOp.kt`（`GradStop`、`gradLut()` 分段插值）、`image/ColorFx.kt`（`gradientMap(src, c1, c2, stops)`）、`ui/ColorFxTools.kt:212` `GradientMapPanel`
- 色带可「＋加色标」，每个中间色标能取色、用细线滑块拖位置、✕ 删除；预览、应用、调整层走同一套 LUT，所见即所得。

## 11. PSD 导出不再丢渐变映射（T12）

- 位置：`ui/EditorScreen.kt` 导出前处理、`ui/SketchView.kt` 新增 `bakeOpIntoBitmap()` / `compositeUpTo()` / `needsBakeForPsd()`
- PSD 的 `GdMp` 块还没实现，所以导出前把「渐变映射」「调整组」这两种图层烘焙成像素层再写（图层名后缀「（已栅格化）」），桌面端打开能看到效果而不是空层。

## 12. 选圆形物体只能得到外接方框（T13）

- 根因不是算法，是入口：椭圆 / 套索 / 多边形只藏在「矩形选框」参数条的「方式」一行里，用户找不到。
- 改法：选区分类里单独列出「椭圆选框 / 套索 / 多边形」三个入口（图标 Circle / Gesture / Timeline）。
