# 0.74.36 修复：四个滤镜画面变成彩色噪点 / 预览锯齿

## 一、油画、水彩、中间值、蒙尘与划痕 画面全是噪点
**真因：并行时把临时缓冲写成了线程共享。**
- `median()`（0.74.34 加的并行）：`rs / gs / bs / asv` 四个数组在 lambda 外面分配，8 个线程同时对同一份数组写入再 `sort()` —— 中值取到别人那一行的像素，画面就成彩色噪点。水彩、蒙尘与划痕都是调 `median()` 的，所以一起坏。
- `oilAt()`（同一批改的）：`count / sr / sg / sb` 四个分箱数组也是共享的，「取众数」读到被别的线程清空的箱子。

**改法**：把这两组临时数组挪进 `Parallel.chunks` 的 lambda 里，做到「每个线程一份私有缓冲」。这样并行度不变、结果和串行完全一致。

## 二、不卡了但画面有锯齿
**真因：`previewPaint.isFilterBitmap = !pixelZoom`。** 预览图是降采样后再放大贴到画布的，100% 缩放下 `pixelZoom` 为真 → 走最近邻 → 低分辨率预览被放大成硬像素块，看起来就是锯齿。
**改法**：预览绘制固定 `isFilterBitmap = true`（双线性），正式图层绘制仍按 `!pixelZoom` 走像素级。同时顺手调整了降档策略。

## 三、降档策略改成「渐进清晰」
- 只有单帧计算超过 **45ms** 才降一档，而且只降到 **640**（不再降到 480，避免糊）。
- 参数停手 **0.4 秒**后自动升回 **900** 重算一次：拖动时跟手、松手后变清晰（桌面端也是这个行为）。

## 没做
0.74.x 全部只编译验证，无真机验收；真实流畅度与清晰度要你上手判断。
