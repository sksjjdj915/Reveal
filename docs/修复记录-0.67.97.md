# 0.67.97（versionCode 355）修复记录

出包时间：2026-11-09　APK：42,480,005 字节　桌面：Reveal-0.67.97-debug.apk

## 用户需求

「软件主页长按加个复制功能，复制后有两个一样的工程」

## 改法

### 1. `data/ProjectStore.kt` 新增复制工程

```kotlin
@Synchronized
fun copy(context: Context, id: String): String?
```

- 新 id：`p + System.currentTimeMillis().toString(36)`，撞了就 +1ms 重试（最多 50 次）。
- 新名字：`原名 + 副本`；已有同名就 `副本 2`、`副本 3`……（对照 `list(context)` 里现有名字，不会重名）。
- 目录整体拷：`project.rvl`、`manifest.json`、`thumb.jpg`、`adjust.rvl`、`project.rvl.bak` 全部照搬（所以复制品能直接打开接着画，缩略图也一样）。
- 两处 manifest 都改名：目录里那份（首页列表读它）和工程包 `project.rvl` 里那份（打开后编辑器标题读它）。为此新增 `private fun rewritePackageName(file, name, updatedAt)`：ZipInputStream 逐条流式搬进临时包，只把 `manifest.json` 这条替换成新内容，其余条目原样 64KB 块搬运——不整包解压重压，几十层的 4096 工程也不会吃爆内存。

### 2. `ui/HomeScreen.kt` 长按弹出小菜单

- 新增状态 `var copyTarget by remember { mutableStateOf<Project?>(null) }`。
- 工程卡片的 `onLongClick` 从「直接进多选」改成 `copyTarget = project`。
- 新增 `AlertDialog`（插在删除确认框之前）：标题是工程名，两行可点：
  - **复制一份**（主题色）→ 协程里 IO 线程 `ProjectStore.copy`，期间顶部显示「正在复制…」，完成 toast「已复制出一份一模一样的工程」并 `reload()`；
  - **多选（批量删除）** → `selMode = true; selected += target.id`（原来的长按多选行为保留，只是多一步）。
  - 取消 / 点外面关掉，什么都不做。
- 复制失败（工程文件读不到）toast「复制失败：工程文件读不到」。

## 验法

1. 首页长按任一工程 → 弹窗出现两行选项。
2. 点「复制一份」→ 顶部先出「正在复制…」，稍后 toast「已复制出一份一模一样的工程」。
3. 列表里多出一条「XXX 副本」，缩略图和原工程一样。
4. 打开副本，标题是「XXX 副本」，图层/大小/内容跟原件一致；改副本不影响原件。
5. 再复制一次同一工程 → 出现「XXX 副本 2」。
6. 长按 → 「多选（批量删除）」仍能进多选模式。

## 没做的

- 复制用单线程顺序拷贝：4096 多图层大工程（几百 MB）会转圈几秒，但不会崩（每个文件独立 copy，失败只跳过该文件）。要不要改成带进度条的复制，等用户觉得慢再说。
- 没有做「复制时可以顺便改名」——名字固定加「副本」，改名走别的入口（`ProjectStore.rename` 已有）。
