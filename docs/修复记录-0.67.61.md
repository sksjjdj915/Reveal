# 0.67.61 修复记录

## 这一版改的是「从 QQ 打开」的做法（按你定的口径）

你的原话：「从 QQ 打开就是确定文件位置，然后软件只是显示，点一下复制」。

以前（0.67.38 起我改坏了）是：对方递来文件 → 立刻复制 → 直接跳进编辑器。
问题是：一旦读不到（比如 QQ 分身里的文件），用户立刻被怼在一个报错上，连首页卡片这一步都看不到。

现在：

1. **从 QQ 打开＝只登记位置**：不读文件、不复制，只记住「URI + 文件名」，首页立刻出一张卡片。
2. **点卡片才复制**：这时才真的把文件拷进软件目录（还是老配方：能拿 FD 就 8MB 分块映射拷贝、拿不到就 1MB 流式、退避重试、落盘前验 `8BPS` 文件头），然后备份成工程并进编辑器。
3. **报错挪到点击那一刻**：分身隔离、权限没给、不是 PSD、0 字节，都在点卡片时用可复制对话框说清楚，不再一打开就崩一脸。
4. **不再自动进编辑器**：打开文件只回首页、卡片摆出来，点它才进画。

## 具体改动

- `data/Incoming.kt`
  - 新增 `class Pending(id, uri, name, time)`、`pendings(context)`、`register(context, uri)`、`removePending(context, p)`。
  - 登记表存 `filesDir/incoming_pending.txt`，一行一条：`时间\t文件名\tURI`，最多留 20 条；同 URI 只留最新。
  - `register` 只从 URI 最后一段取名字（取不到才去问 provider），**不打开文件**，所以读不到也不影响出卡片。
- `MainActivity.kt`
  - `RevealApp` 的 `LaunchedEffect` 从「复制 + 备份 + 进编辑器」改成一句 `Incoming.register(context, uri)`。
- `ui/HomeScreen.kt`
  - 新增 `pendings` 状态，`reloadIncoming()` 里一起读；标题改成「QQ / 微信发来的（点一下才复制）」，待复制卡片排在已落盘卡片前面，缩略图位置留灰底。
  - 点待复制卡片：`busyText = "正在复制文件…"` → `Incoming.add(...)` → 成功后 `removePending` → `PsdFiles.backupFile` → 进编辑器；失败弹可复制对话框（并写日志）。
  - 长按待复制卡片＝不要这个文件（只删登记，不删任何文件）。

## 已知边界

1. 登记表能跨重启，但**系统给的读取授权不一定跨重启**。重启后点老卡片若失败，会提示位置失效/没权限，请从 QQ 再发一次——这是 Android 的授权模型。
2. 待复制卡片暂时没有缩略图。要出预览就得读文件，跟「不碰文件」冲突；你说要我再加（可以只在点开时解码一张小图）。
3. 同名文件不互相覆盖：复制成功后按新名字落盘，旧的同名卡片被替换。

## 怎么验

1. QQ 里点 `00_主流程.psd` →「用其他应用打开」→ Reveal：应回到首页，出现灰底卡片，**不跳编辑器、不弹报错**。
2. 点那张卡片：出现「正在复制文件…」→ 复制完进编辑器，图层/蒙版/半透明都对。
3. QQ 分身（URI 带 `/emulated/999/`）：点卡片后才弹「跨分身读不到」，并给「长按文件→保存到手机→用＋导入」的办法。
4. 长按卡片：卡片消失，软件目录里不产生任何文件。
5. 杀掉进程重开：卡片还在；点它若失败，会提示位置失效。
