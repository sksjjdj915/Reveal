## A 档：直接影响手感，必须先换（用户已经能感觉到卡）

| # | 功能 | 现在怎么做 | 主流做法（文献） | 收益 | 影响桌面端导出？ |
|---|---|---|---|---|---|
| A1 | 笔迹渲染 | 沿路径**逐笔头贴位图**（软边靠密集叠加），一笔 1000~4000 次贴图，实测盖章 357ms/3 次移动 | 一条路径/描边一次画；软边用模糊描边或 GPU 笔刷 shader（Procreate / Infinite Painter / Krita 的 stroke engine） | 每次移动从 55~120ms → 个位数 ms | 否（只改绘制，不改像素格式） |
| A2 | 笔头间距 | 直径的 12%（`brushSize*0.12`） | 桌面端默认 25% 直径；纹理笔刷才需要更密 | 笔头数直接减半 | 否 |
| A3 | 笔迹预览 | 屏幕位图累积 + 脏矩形重绘 | 前缓冲直接画（Android 14 低延迟触控笔 front-buffer API）+ 指针预测（`MotionEvent` 历史点/预测点） | 进一步降延迟、拐弯更圆 | 否 |
| A4 | 图层合成 | 每层整幅位图 + 一张视图空间合成缓存 | 瓦片 + 脏区重建（Krita tile / GIMP projection） | 30 层文档滚动/缩放不再整幅重合 | 否 |
| A5 | 撤销记录 | 整块像素 Patch（大图一次几十 MB） | 瓦片级差异（Krita/Krita-like tile diff） | 大图撤销内存降一个数量级 | 否 |
| A6 | 选择蒙版 | 全幅 `byte[]`，部分操作整幅扫描 | 稀疏/瓦片蒙版 + 脏区更新（GIMP mask tile） | 有选区时缩放不再卡 | 否（写 PSD 时再转成图层蒙版） |

## B 档：质量/效果明显更好，但不卡

| # | 功能 | 现在怎么做 | 主流做法（文献） | 收益 | 影响桌面端导出？ |
|---|---|---|---|---|---|
| B1 | 缩放/旋转重采样 | `Bitmap.createScaledBitmap`（双线性） | mipmap + Lanczos（Krita 用 3 次 box 近似高斯） | 缩小后细节不糊、不闪 | 否 |
| B2 | 高斯模糊 / 降噪 | 箱式模糊多次近似 | Stack Blur / 三次箱式（Kawase）分块多线程 | 同类效果快 2~4 倍 | 否 |
| B3 | 色阶/曲线/调色 | 部分逐像素 Java 循环 | 先建 256/65536 项 LUT，再分块查表（GIMP/桌面端同思路） | 调色预览实时 | 否 |
| B4 | 液化/透视变换 | CPU 逐像素反向映射 | 网格 warp + 双线性（桌面端的 Liquify mesh、Krita transform mask） | 拖动时能实时预览 | 否 |
| B5 | 选区羽化/收缩扩张 | 盒式/半径扫描 | 距离变换（Felzenszwalb EDT）+ 二项式平滑 | 羽化过渡更自然、边界不发硬 | 否 |
| B6 | 文字排版 | 自绘 `nativeCanvas.drawText` | `StaticLayout` + `Typeface` shaping（支持换行/字距/竖排） | 中文断行、行距更准 | 是：PSD 文字层要写正确的 transform + 字体名，需补丁 |
| B7 | 图像缩放导出 | 按需要缩放后再编码 | 一次解码 → 目标尺寸直接采样（避免二次重采样） | 导出更快更清 | 否 |
| B8 | 画笔动态（压感/倾斜/速度） | 已有 8 档笔尖 + 抖动/纹理 | 与 Procreate 一致：pressure→flow/size、tilt→scatter、velocity→taper | 笔迹更"活" | 否 |

## C 档：桌面端兼容性（不属于性能，但属于"照桌面端"）

| # | 项 | 现状 | 做法 | 备注 |
|---|---|---|---|---|
| C1 | 16 位 / 32 位 | 已有 Pix16/Pix32，读写有限制 | 按桌面端规范补齐 16 位图层段（已有 16 位 ZIP 只读） | 导出时 8 位回退，避免桌面端打不开 |
| C2 | 图层蒙版写入 | 读支持、写部分 | 按 `LMsk` 段规范写，蒙版与图层尺寸/偏移对齐 | 必须用桌面端当 oracle 验证 |
| C3 | 调整图层 | 读支持、写未做 | 写 `AdjL`/`TySh` 之外的 `SoCo`/`Lev ` 段 | 先做曲线/色阶两类 |
| C4 | 图层不透明度 | 已修（178→69.8% 归整问题） | 保持"先归整百分比再乘 2.55" | 已完成 0.67.71 |
| C5 | 智能对象 | 读支持（PsdSmart） | 写时不展开，保留原始嵌入数据 | 低优先 |
| C6 | 色彩配置 | sRGB 内嵌（SrgbProfile） | 导出时 embed sRGB profile | 已具备 |

## 建议的落地顺序

1. **A1+A2**（笔迹描线化 + 间距 25%）——解决跟手，收益最大，风险最小（只碰 `SketchView` 绘制路径）
2. **A4+A5**（瓦片合成 + 瓦片撤销）——为 30 层/4096 打底，改完 A1 再动
3. **B1/B3/B5**——画质类，一次做一组，用固定测试图做前后对比
4. **C1~C3**——每次都用"桌面端打开验证"当判据（我们有 jsx 存参照文件的套路）
5. **A3/A6/D1~D4**——按用户反馈排
