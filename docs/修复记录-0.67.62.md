# 0.67.62 修复记录

## 起因

你问：「为什么我之前用 QQ 分身的都没问题？之前全是 QQ 分身。」
我上一版（0.67.60）看到 URI 里有 `/emulated/999/` 就一口断定「跨分身读不到，重试无用」——**那是猜的，不该写死成结论**。这版把猜测去掉，改成当场取证。

## 从日志能确定的事实（不是推断）

`D:\qq\1\Reveal日志-1108-1808.txt`（注意：那份日志的版本是 **0.67.58**，不是 0.67.60）：

```
INTENT action=VIEW flags=0x10000001（read=true）
  authority=com.tencent.mobileqq.fileprovider
  uri=content://com.tencent.mobileqq.fileprovider/external_files/storage/emulated/999/.../00_主流程.psd
RECV 接收失败 … 异常：java.io.FileNotFoundException: No content provider: content://com.tencent.mobileqq.fileprovider/…
```

`No content provider` 是系统在**解析 provider 这一步**就失败了：系统说「这个地址找不到能读取的组件」。也就是说，失败发生在拿到文件之前，跟文件大小、格式、我们的解析都无关。

## 这版做了什么

1. **去掉「跨分身」这种硬结论**：不再据此提前判死，文案只描述事实。
2. **每次尝试都记异常**：`openFileDescriptor #1..#4`、`openInputStream #1..#3` 各自失败的类型和原文（截断 160 字）都写进记录。
3. **加现场探测**，失败弹窗里会多出三行：
   - `provider「com.tencent.mobileqq.fileprovider」在本空间：能解析（包名）/ 解析不到`
   - `QQ 主空间版本：x.y.z / 没装`
   - `我的 uid=xxx（user=0）`
   这三行能一锤定音：
   - 写「解析不到」→ 这个 authority 在我们所在用户空间确实不存在（分身隔离成立）；
   - 写「能解析」→ 隔离不成立，是 provider 自己拒绝/文件不在那个路径，我按真实异常继续查。
4. 复制流程、登记位置、点一下才复制这些都没动。

## 你怎么验（1 分钟）

1. 装 0.67.62。
2. 在 QQ 里点 `00_主流程.psd` →「用其他应用打开」→ Reveal，首页出卡片。
3. 点卡片，失败后把弹窗内容复制发我（现在里面带上面那三行 + 每次尝试的异常）。

另外：如果只是想先把图打开干活，`长按文件 → 保存到手机 → 首页＋ → 从文件管理器选` 这条路一定能通。
