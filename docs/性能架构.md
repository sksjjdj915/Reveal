# Reveal 性能架构（地基）

版本：v0.40 起
目标：5000×5000、10 图层的 PSD，能流畅缩放/绘制，不 OOM，手机（≥6GB）可用。

## 一、现在的瓶颈（诊断结论）

| 症状 | 根因 |
|---|---|
| 大图直接 OOM / 闪退 | 图层是**整张画布尺寸的 ARGB_8888 位图**。5000×5000×4 = 100 MB/层，10 层 = 1 GB |
| 缩放后拖动卡 | 每帧把 N 张整幅位图按 `drawBitmap(src,dst)` 缩放绘制，缩到 20% 时每帧采样 5000² 像素 |
| 画笔有延迟 | 笔迹直接写进图层位图，改 1 个像素也要整层重新合成、整层重绘 |
| 撤销占内存 | 脏矩形 Patch 存的是位图副本，连续大笔划很容易吃掉几十 MB |

## 二、业界做法（参考文献）

1. **桌面端**：固定 256×256、8 位/通道的 **tile**，配 **mipmap 金字塔**（缩小时用低分辨率层），写时只重算受影响 tile；大文件靠 tile 的 LRU 换页到磁盘。（Scott Byer《桌面端 Frameworks》系列；桌面端文件格式的分层数据本身就是"每层再按 tile/RLE 压缩"的结构。）
2. **Krita**：`KisTiledDataManager` + `KisTileData`，tile 尺寸固定 `KisTileData::WIDTH/HEIGHT`（64×64），稀疏哈希表存 tile，写时按 tile 分配 copy-on-write；`KisMipmapPaintDevice` 提供金字塔。
   参考：<https://invent.kde.org/eoinoneill/krita/-/blob/72a0511495115d4d4a275784e35b01d65514448d/krita/image/tiles3/kis_tile.h>、<https://invent.kde.org/eoinoneill/krita/-/blob/5fcaf86131e99e844bef3b151e7923cc756e12d3/krita/image/tiles3/kis_tiled_data_manager.cc>
3. **GIMP**：tile cache（64×64），"dirty tile" 集合 + 后台 swap 到磁盘（`tile-manager.c` / `tile-cache.c`）。
4. **Android 侧**：`Bitmap.Config.HARDWARE` 只读、不能 `Canvas` 绘制，适合当"已合成结果的缓存"；`RenderNode`/硬件加速 Canvas 能把静态内容缓存成 display list；`Canvas.saveLayer` 代价高，要避免每帧调用。

## 三、方案（分四层，逐层可独立验收）

### L1 存储：分块 + 稀疏 + LRU
- 画布按 **256×256** 切 tile（与桌面端一致；手机上比 64×64 少 16 倍的索引开销）。
- 图层 = `SparseArray<TileRef>`（只存非空 tile，透明区域不占内存）。
- 每 tile 256×256 ARGB_8888 = 256 KB。内存预算按 `Runtime.maxMemory()` 的 45% 算，超了就 **Deflate 压到内存、再超就落盘**（`filesDir/tiles/<layerId>/<x>_<y>`）。
- 画布 ≤ 4000×2000（≈8 MP）时不启用分块，保留整幅位图，避免小图变慢——**分块只在超过阈值时启用**。

### L2 渲染：视口合成缓存 + 脏矩形
- 只合成"屏幕能看到的那块"到一个屏幕大小的 `Bitmap`（合成缓存）。
- 记录 `dirtyRect`，绘制/缩放/图层变化时只重合成脏矩形，其余帧直接贴缓存。
- 画笔在**笔迹专用 overlay 层**上画，松手才合并回图层，避免每次采样都重合成整块。

### L3 缩放：二级金字塔
- 合成缓存按 1/2、1/4、1/8 维护低分辨率版本；缩放 < 50% 时用对应层级绘制，缩小不再采样原图。
- 缩放/平移只改 dstRect，不重新合成。

### L4 交互：坐标与失效
- 屏幕坐标 → 画布坐标用仿射矩阵一次算好，所有工具统一走它。
- 只有"真正改了像素"的 tile 才进脏集合，脏集合驱动重合成 + 重绘。

## 四、验收数字（可量化）

| 项 | 现在 | 目标 |
|---|---|---|
| 打开 5000×5000 / 10 层 PSD | 大概率 OOM | < 6 s，峰值内存 < 400 MB |
| 缩放到 20% 时拖动 | 掉帧 | ≥ 50 fps（模拟器 swiftshader 允许打 5 折） |
| 单笔 Studio 级笔刷落笔延迟 | 明显 | < 60 ms |
| 连续 50 笔后内存增长 | 线性涨 | < 50 MB |

## 五、实施顺序（一次一版，每版都能量）

1. **v0.40.0**：L2 视口合成缓存 + 脏矩形（不动存储结构，风险最低，立刻能测出帧率差异）。
2. **v0.41.0**：L3 金字塔。
3. **v0.42.0**：L1 分块存储（大图才启用）+ 打开时后台线程与进度。
4. **v0.43.0**：笔迹 overlay 层。
