# 0.74.33 事故修复：FilterFx.kt 被脚本截断后重建

## 发生了什么（必须记下来）
0.74.32 之后我想把「行级并行」批量套到 10 个重滤镜上，用 python 做「找循环 → 包一层 Parallel.rows → 补一个闭合括号」的机械变换。
第一步变换把 `return` 放进了 lambda（Kotlin 不允许非局部 return），编译报 `'return' is prohibited here`；
我又写了个反向还原脚本，还原时的「删掉多余闭合括号」逻辑写错，**把 FilterFx.kt 从 828 行截成了 62 行**，后面 30 多个滤镜实现全没了。

## 怎么恢复的
1. `git status` 发现这个文件在索引里有暂存版本（` M`），`git checkout -- <file>` 从索引恢复到 827 行——这是 0.74 初期的版本，**不含今天新加的 9 个函数**。
2. 再把缺的 9 个按原有公式重新写回（都在 `docs\修复记录-0.74.19`~`0.74.29` 里有算法依据）：
   `mosaicAt`、`pinchAt`、`spherizeAt`、`twirlAt`、`polarAt`、`rippleAt`、`lensFlareAt`、`watercolorAt`、`oilAt`。
3. `findEdges` 重新加回 `threshold` 参数（默认 0 = 桌面端原样），参数面板里的「阈值」滑块保留。
4. 编译通过、出包（code 461）。

## 现在的状态
- 功能面：与 0.74.32 一致（9 个子滤镜参数 + 查找边缘阈值 + 自适应预览分辨率）；
- **行级并行已全部撤回**：`Parallel.kt` 还在，但目前没有滤镜在用；批量套并行这条路走不通（大量函数体内有 `return`），要改成「逐个函数手工改造」。

## 教训（已入库）
- 对含 `return` 的函数做「包 lambda」的机械变换必然失败；
- 批量文本变换后必须立刻编译 + 数行数，别等第二个脚本再动同一文件；
- 工程里 `git checkout -- 文件` 只能救回**索引里的版本**，救不回今天未暂存的改动，所以每轮改完该 `git add`。

## 没做
重滤镜的并行化要逐个手工做（动感模糊/径向模糊/表面模糊/中间值/尘痕/减噪/最小/最大/加噪/胶片颗粒/油画/水彩/球面化/镜头光晕）。0.74.x 仍只编译验证，无真机验收。
