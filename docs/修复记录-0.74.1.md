# 0.74.1 按文献修拖动/加点

## 查到的依据
1. 《Jetpack Compose 自定义触摸反馈》（compose-museum/jetpack-compose-book）明确指出：`pointerInput(vararg keys)` 的 **keys 一变，正在处理的手势协程会被中断**：
   > “keys：当 Composable 组件发生重组时，如果传入的 keys 发生了变化，则手势事件处理过程会被中断。”
   这就是「只能拖一小段 / 点一次算一次」的根因——之前我把点表、黑白场数值当成了 key。
2. 同文给出的低层写法是 `forEachGesture { awaitPointerEventScope { awaitFirstDown(); drag(id) { ... } } }`，由 `drag()` 负责按手指 id 连续跟踪，不会每帧重建。
3. Android 官方 `pointerInput` 参考文档同样说明 key 用于「重启 handler」，只有需要换检测逻辑时才该变。

## 这次改动
1. **色阶黑白场**：改成低层 `awaitEachGesture + awaitFirstDown + drag(down.id)`，`pointerInput(Unit)` 固定；拖动量用 `change.position - change.previousPosition` 逐帧累加，`inBlack/inWhite` 通过 `rememberUpdatedState` 读最新值——不会再被重组打断，能一口气拖到底。
2. **曲线加点/拖点**：0.74.0 已改成单手势循环（`awaitEachGesture`），这次把交互口径写清楚并统一：
   - 拖已有点＝移动（端点只上下，中间点可左右）；
   - **点空白＝加一个点**（单击即可，不用连点）；
   - **点已有的点＝删掉它**（端点不可删）。
3. 面板里的说明文字同步改成上面这套口径。

## 没做
文字参数、液化变形、裁剪与图像大小、AI；曲线吸管/自动按钮。
