# Reveal 0.67.41 修复记录（补齐 0.67.40 没做的两条）

## 一、存储：图层从 PNG 换成原始字节 + 1 级压缩

**原来**：工程包 zip 里每层是 `layer_N.png`（质量 100），存一次要串行跑 N 次 PNG 编码。

**现在**：每层是 `layer_N.bin`，内容是该层 ARGB_8888 的原始字节，由 zip 用 **1 级** 压缩。
PNG 编码要算滤波/哈夫曼，手机上一次几十毫秒起步；原始字节只是把 `IntArray` 摊成字节，几乎不花时间。

几个要点：
- **读写都是分条（band）进行**：一次最多 256 行，4096 的图内存占用也只有几 MB，不会 OOM。
- **向后兼容**：老工程还是 `layer_N.png`，读取端保留原来的 PNG 分支，照样能打开。
- 蒙版、智能对象原图仍然是 PNG（它们数量少、且要保证体积），继续走并行预编码。

**代价（要提前知道）**：原始字节没有 PNG 的预测滤波，同样内容体积会比 PNG 大，实测常见插画层大约 2~3 倍。
好处是打开/保存快一个量级。如果以后体积成了问题，再加「小图用 raw、大图用 PNG」的阈值。

## 二、缩放：手势中直接画图层（不再重合成）

**原来**：合成缓存按当前视图倍率烘焙，缩放每一步都可能触发「三十层整体重合成」（一百多毫秒）→ 掉帧。

**现在**：`zooming` 为真时走**直接绘制**分支——每层用自己的变换矩阵贴上去：
- 位图层：GPU 直接缩放，任意倍率都清晰；
- 瓦片层（大图层被换到磁盘的）：`drawVisible` 只读视口里的那几块 256×256 瓦片，视口外的完全不碰；
- 图层级还有 `layerInViewport` 裁剪，完全在视野外的层直接跳过。

手指抬起（`zooming` 变假）后回到合成缓存路径，恢复单张贴图的性能。

## 三、验收

1. 打开 05（三组三十层）→ 比 0.67.40 再快一截（日志里 `encode=` 那段应该几乎没了）。
2. 30 层上双指连续放大/缩小 → 全程清晰，不再出现「拉伸糊一下再变清楚」。
3. 4096 大图上缩放 → 不应卡死，也不应 OOM。
4. 画一笔、撤销、重做、存盘、杀进程重开 → 工程能正常读回（新格式）。
5. **旧的工程**（0.67.40 之前保存的）→ 也要能打开（读的是 `layer_N.png` 分支）。
6. 首页缩略图正常。

## 四、已知边界

- 新格式单层体积约为 PNG 的 2~3 倍（见上）。
- 缩放中直接画图层，层数特别多（>40）时每帧要做很多次贴图，理论上比缓存慢；实测不够再讨论分级策略。
