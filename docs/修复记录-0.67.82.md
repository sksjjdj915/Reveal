# 0.67.82 修复记录（2026-11-08）

## 1. 裁剪：四角能斜着拖了（A3 变正方形的真因）

读码确认：`SketchView.cropHandles()` 返回的顺序是「四角 + 四条边中点」，但 `cropBeginDrag()` 一律用 `cropMode = 2 + i` 编号，而 `cropDrag()` 里 2/3/4/5 分别是「左/上/右/下**单边**」。

⇒ 拖左上角只改左边、拖右下角只改右边、拖左下角只改左边、拖右上角只改右边——**角没有「两个方向一起改」的行为**。

于是「从头顶上方拖到腰下」这个动作，实际把**下边**一路往上收，收到 1080 时就变成了正方形。

改法：
- 角点单独给编号 10..13（左上/右上/右下/左下），`cropDrag()` 里新增四个分支，同时改两条边，带 24px 最小尺寸；
- 边中点仍走 2..5 / 6..9 的单边逻辑。

## 2. 裁剪/旋转/透视之后，右上角尺寸跟着刷新

`EditorScreen` 的 `view.onDocChanged` 里补：

```kotlin
view.activeLayer?.bitmap?.let { docInfo = "${it.width} × ${it.height}" }
```

之前只有「图像大小 / 画布大小」会刷新，裁剪后标签还停在旧尺寸，看着像「裁剪没生效」。

## 3. 图像大小 / 画布大小：对话框预填当前尺寸

侧栏「分类 → 变换 → 图像大小/画布大小」之前只 `showResize = true`，没填初始值，所以两个框是空的（用户报「前两个没有显示数字」）。改成和「菜单 → 图像」一致：先读 `sketch.activeLayer.bitmap` 的宽高再打开。

## 怎么验

1. 分类 → 变换 → 裁剪：拖左上角往右下、拖右边往左，两个方向都能同时动；把框拖成任意长方形都行。
2. 裁剪完点应用，右上角尺寸立刻变成裁剪后的数字（例如 1080 × 940）。
3. 分类 → 变换 → 图像大小：打开时宽高已经填好 1080 / 1620，不用自己敲。
