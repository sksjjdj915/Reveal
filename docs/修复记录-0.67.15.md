# Reveal 0.67.15 修复记录（第二轮：把没做透的补上）

版本：versionCode 280 / versionName 0.67.15
APK：42332385 字节（com.reveal.editor）
本轮在 0.67.14 的基础上补 4 个没做透的点 + 清掉 2 处死代码。桌面测试文本 `Reveal-测试案例.txt` 仍未改动。

## 补上的四件事

### 1. 污点修复「近似匹配」改成块匹配
原来只比「候选点那一个像素」和目标像素的颜色差，所以经常挑到纹理完全不同的地方，贴上去一坨。
现在比候选点周围 3×3 与目标周围 3×3 的像素差之和（`ToolFx.patchDiff`），纹理走向也参与打分，挑更「像同一块皮肤/同一段头发」的整块搬过来。

### 2. 颜色替换「限制：连续」真的按连通算了
原来连续和不连续长得几乎一样（都是笔刷范围内符合容差就换），只有「查找边缘」有区别。
现在 `SketchView.buildReplaceLimit` 维护一张「这一笔已经换过哪些像素」的连通图：
- **连续**：只有和落点（或已经换过的区域）连着的同色像素才会被换。笔刷压到一块不连着的小色块（比如红底上一个小蓝点），它不会被一起换掉——
  以前这就是「红换红」「换个色把旁边的也带走了」的来源。
- **不连续**：笔刷范围内所有符合容差的像素都换，不管连不连。
- **查找边缘**：保留原来的「跳过颜色跳变处」。

### 3. 「样本 = 所有图层」不再卡第一笔
仿制图章 / 修复画笔 / 涂抹在「所有图层取样」时，以前每次落笔都在主线程把整幅拍平一次（4000px 以上文档会顿一两百毫秒）。
现在 `SketchView.flatSnapshotOrNull()` 把这活放到后台线程，拍好的结果缓存起来；这一笔还没拍好就先拿当前图层顶着，不会卡。
缓存会在「一笔画完」「撤销」「重做」「换文档」「重新取样」时作废，保证取的永远是最新画面。

### 4. 选区内侧常亮细边 + 百分比不再整幅读图
- 选区边界内侧加了一根 1px 浅蓝常亮线（`selInnerPaint`）：画面很暗时黑白蚂蚁线看不清，这根线一直在。
- `maskPercent` 以前整幅 `getPixels`（4096² 要分配 64MB，每次判「选了多少」都卡一下），改成逐行读 + 大图隔行采样。

## 清掉的两处死代码（不改行为，只是以后别改错文件）

1. `SketchView.commitToneStroke`：全工程无调用点，和真正生效的 `toneApply` / `drawToneSegment` 是两套算法。留着迟早有人改到它上面，删掉。
2. `ToolOptions.kt` 里 `CLONE / HEAL`、`DODGE / BURN`、`SMUDGE` 三条分支：`PsToolOptionsHost` 的入口列表里根本没有这三个工具，真正的参数条在 `EditorScreen.kt` 的 optionsStrip 里。删掉后参数条只剩一处，不会再出现「改了一个文件没反应」。

## 关于「每个工具独立笔刷大小」

上一版说的这条其实已经满足，只是没讲清：橡皮擦和背景橡皮擦用自己那套独立字段（`eraserSize` / `bgEraserSize`），其余画笔类工具靠 `toolSizes` 记忆各自的大小，切换工具互不影响。这是有意的设计，不是漏做。

## 仍然没做到位的地方

1. 污点修复是「候选块评分」，不是桌面端那种完整的 PatchMatch 迭代搜索——够用，但极端纹理（细密发丝）上位不会完全追平桌面端。
2. 颜色替换的「查找边缘」还是用容差近似跳过跳变，没有算真正的边缘梯度。
3. 「所有图层取样」的第一笔（缓存还没拍好时）实际取的是当前图层，第二笔起才是全部图层。这是拿「不卡」换的，写在这里免得当成 bug。
