# 0.67.87 修复记录（2026-11-08）

## 背景

动感模糊点「确定」闪退后，用户打开首页「日志」只看到两行（`APP START` + 自检 `IMPORT`），
没有任何崩溃信息。查代码发现两个真问题：

1. **崩溃堆栈写在另一个文件里**：`Thread.setDefaultUncaughtExceptionHandler` 把堆栈追加到
   `filesDir/reveal_crash.txt`（`CrashLog`），而首页「日志」只读 `filesDir/diagnose.log`（`Diag`）。
   ⇒ 崩溃记录一直在写，但用户从来没看到过。
2. **启动时清空日志**：`RevealApplication.onCreate` 里每启动一次就 `Diag.clear(this)`，
   上一次闪退前的诊断记录随之被抹掉。

## 这次改了什么

- `RevealApp.kt`：启动时不再 `Diag.clear()`，只追加 `APP START`；历史长度交给 `Diag` 的滚动上限管。
- `data/Diag.kt`：超过 256KB 不再整份删掉，而是保留最后 120KB 并加一行「更早的记录已滚动掉」。
- `ui/HomeScreen.kt`：首页「日志」弹窗标题栏右边分成两个页签 **诊断** / **崩溃**，
  点哪个看哪个，互不混在一段文字里；「复制」复制的是当前这一页的内容。

## 怎么用（下次闪退）

1. 复现闪退 → 重新打开 App
2. 首页右上「日志」
3. 点标题栏右边的 **崩溃** → 里面就是那次闪退的机型、版本、异常类名和完整堆栈
4. 点「复制」，把整段发我

诊断那条线（导入/裁剪/滤镜的普通记录）仍然在 **诊断** 页，两边分开，不会互相覆盖。

## 注意

崩溃记录文件上限 64KB，超过会自动保留最后一截（`CrashLog` 原有逻辑）。
如果这次装的是 0.67.87 之前的包，那次闪退的记录已经被旧的 `Diag.clear()` 清掉了，
需要带新包再复现一次才能抓到。
