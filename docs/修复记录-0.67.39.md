# 修复记录 0.67.39（code 304）

日期：2026-11-08

## 现象（用户实测很多次）

QQ「用其他应用打开」发 PSD 给 Reveal：

- **第一次基本失败**，多试几次就能成功；
- 失败时没有任何可复制的信息，日志里只有一句「对方没把读取权限给过来」。

## 真因：不是权限，是「时机」

`Incoming.add()` 只尝试**一次** `openFileDescriptor`，失败就判死刑。而第一次打开时 QQ 往往还没把文件从聊天缓存里取到 `QQfile_recv/`，或者授权比 Intent 晚到几十/几百毫秒——于是第一次必然扑空，第二次再点 QQ 已经准备好了，就成功了。这和你说的「多试几次就行」完全对得上。

而且原来 `runCatching{...}.getOrNull()` 把 **FileNotFoundException（还没准备好）** 和 **SecurityException（真没授权）** 糊成同一个 null，全报成「权限」——误导了我上一轮的判断。

## 改法

1. **退避重试**：`openFileDescriptor` 试 4 次（200ms、350、700、1050ms），仍失败再换 `openInputStream` 试 3 次（每次 300ms）。最多多等约 3 秒，成功就直接进编辑器。
2. **不再把异常吞掉**：失败时按真实异常给话——
   - `FileNotFoundException` → 「QQ 还没把这个文件从聊天里取出来（第一次打开常这样，等一秒再点一次）」
   - `SecurityException` → 「对方没把读取权限给过来（QQ 分身/多账号里的文件，系统不允许跨沙箱授权）」
   - 其它 → 原文
3. **记录 Intent 现场**：每次收到文件都往日志写一条 `INTENT`，含 `action`、`flags`（十六进制）、**有没有 `FLAG_GRANT_READ_URI_PERMISSION`**、`authority`、`uri`。下次一眼就能分清是「QQ 没给」还是「给了但我们读晚了」。
4. **诊断框加「从文件管理器选」**：失败弹窗里多一个按钮，直接跳到系统文件选择器（那条路有持久授权）。

## 怎么验

1. 杀掉 Reveal，从 QQ 里第一次发一个 PSD → 应该**不再失败**；就算第一次扑空，重试也会在 1~2 秒内自动补上并直接进编辑器。
2. 故意发一个很大的 PSD → 卡片显示「正在接收… N%」。
3. 如果仍然失败，点「日志」→ 看 `INTENT` 那条：`read=true` 说明授权给了、是别的毛病；`read=false` 就是 QQ 没授权，只能「保存到手机」再选。

## 已知边界

- 重试期间最多多等约 3 秒；超大文件复制更久，但卡片有百分比。
- 若 QQ 真的没给读取授权（`read=false`），App 侧无法补救，唯一出路是「QQ 里保存到手机 → 首页 ＋ → 打开 PSD」。
